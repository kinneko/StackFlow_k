# LLMフレームワーク仕様書

## 1. はじめに

本文書は、大規模言語モデル（LLM）を活用したアプリケーションの構築と展開のために設計された、柔軟かつ拡張可能なプラットフォームである`llm_framework`の仕様を概説します。

**目的:**

`llm_framework`の主な目的は、音声テキスト変換、テキスト音声合成、コンピュータビジョン、LLMインターフェースなどの様々な処理ユニットを統合し、洗練されたAI駆動型アプリケーションを作成するための、標準化され、モジュール化され、スケーラブルな環境を提供することです。複雑なLLMベースのワークフローの開発、展開、管理を簡素化することを目指しています。

**全体アーキテクチャ:**

`llm_framework`は、**StackFlowベースのアーキテクチャ**に基づいて構築されています。これは、データが相互接続された処理ユニットのスタックを流れ、各ユニットが特定のタスクを実行し、その出力をシーケンス内の次のユニットに渡すことを意味します。

これらのユニット間の通信は、高性能な非同期メッセージングライブラリである**ZeroMQ（ZMQ）**によって促進されます。ZMQは信頼性が高く効率的なデータ交換を保証し、異なるプロセスや異なるマシン上で実行される可能性のある分離されたユニットを可能にします。

## 2. コアコンポーネント（ユニット）

このセクションでは、`llm_framework`の構成要素となる個々の処理ユニットについて詳述します。各ユニットは、特定の責任を持つ自己完結型のモジュールとして設計されています。

---

*   **llm-sys（システム/オーケストレーションユニット）**
    *   **目的:** StackFlowフレームワークの主要制御ユニット。他の処理ユニットの初期化、設定、接続（リンキング）、リセットを担当します。全体的な状態とデータフローパイプラインを管理します。
    *   **入力:** 「reset」、「setup」（他のユニット用）、「link」（他のユニット間）などの操作のためのJSONメッセージ。通常、外部インターフェース（例：UART、TCP）からコマンドを受信します。
    *   **出力:** 要求された操作のステータス（例：ユニット設定やリンキングの成功/失敗）を示すJSONレスポンス。
    *   **設定:**
        *   グローバル設定を管理します。
        *   他のユニットの設定パラメータを受信します。
        *   操作例：
            ```json
            {
                "request_id": "11212155",
                "work_id": "sys",
                "action": "reset"
            }
            ```

---

*   **llm-audio（オーディオ入出力ユニット）**
    *   **目的:** システムオーディオサポートを提供します。これには、入力デバイス（マイク）からのオーディオキャプチャや、ワークフローにおける特定の役割（例：`sys.pcm`はKWSやASRのような他のユニットの入力ソースとしてよく使用され、TTSユニットの出力先となることもあります）に応じて出力デバイスへのオーディオ再生が含まれる場合があります。
    *   **入力:** 設定用の制御メッセージ。オーディオ再生の場合、ZMQソケット（例：TTSユニットから）経由でオーディオデータ（例：PCMストリーム）を受信します。
    *   **出力:** オーディオデータ（例：`sys.pcm`）をZMQストリームとして他のユニット（KWS、ASRなど）に提供します。`sys.pcm`形式はRAWオーディオデータを示唆します。
    *   **設定:** 特定のオーディオデバイス設定（例：入力デバイスID、出力デバイスID、サンプルレート、チャンネル数）。READMEには明示的に記載されていませんが、その役割から推測されます。

---

*   **llm-kws（キーワードスポッティングユニット）**
    *   **目的:** キーワード検出ユニットであり、キーワードウェイクアップサービスを提供します。オーディオストリームを監視し、事前定義されたキーワードが検出されるとイベントをトリガーします。
    *   **入力:** ZMQソケット（通常は`llm-audio`から）経由のオーディオストリーム（例：`sys.pcm`）。
    *   **出力:** キーワード検出を示すシグナルまたはメッセージ（例：`kws.bool`）をZMQソケットに出力します。この出力は、他のユニット（ASRやLLMなど）にリンクしてそれらをアクティブ化するために使用できます。
    *   **設定:**
        *   `model`: 使用するキーワードスポッティングモデル（例："sherpa-onnx-kws-zipformer-wenetspeech-3.3M-2024-01-01"）。
        *   `response_format`: 期待される出力形式（例："kws.bool"）。
        *   `input`: オーディオストリームのソース（ZMQトピック名、例："sys.pcm"）。
        *   `enoutput`: ブール値、出力ストリームを有効にするかどうか。
        *   `kws`: 検出する特定のキーワード（例："你好你好"）。
        *   セットアップ例：
            ```json
            {
                "request_id": "1",
                "work_id": "kws",
                "action": "setup",
                "object": "kws.setup",
                "data": {
                    "model": "sherpa-onnx-kws-zipformer-wenetspeech-3.3M-2024-01-01",
                    "response_format": "kws.bool",
                    "input": "sys.pcm",
                    "enoutput": true,
                    "kws": "你好你好"
                }
            }
            ```

---

*   **llm-asr（自動音声認識ユニット）**
    *   **目的:** 音声テキスト変換ユニットであり、音声テキスト変換サービスを提供します。話し言葉をテキスト表現に変換します。
    *   **入力:** ZMQソケット（通常は`llm-audio`から、しばしば`llm-kws`によって起動される）経由のオーディオストリーム（例：`sys.pcm`）。
    *   **出力:** ZMQソケットへの転写済みテキスト（例：`asr.utf-8.stream`）。
    *   **設定:**
        *   `model`: 使用するASRモデル（例："sherpa-ncnn-streaming-zipformer-zh-14M-2023-02-23"）。
        *   `response_format`: 出力テキスト形式（例："asr.utf-8.stream"）。
        *   `input`: オーディオストリームのソース（ZMQトピック名、例："sys.pcm"）。
        *   `enoutput`: ブール値、出力ストリームを有効にするかどうか。
        *   `enkws`: ブール値、KWSとの連携を有効にするかどうか（trueの場合、KWSトリガーを待つ可能性があることを示唆します）。
        *   `rule1`, `rule2`, `rule3`: モデル固有のパラメータ（例：2.4, 1.2, 30.1）。
        *   セットアップ例：
            ```json
            {
                "request_id": "2",
                "work_id": "asr",
                "action": "setup",
                "object": "asr.setup",
                "data": {
                    "model": "sherpa-ncnn-streaming-zipformer-zh-14M-2023-02-23",
                    "response_format": "asr.utf-8.stream",
                    "input": "sys.pcm",
                    "enoutput": true,
                    "enkws":true,
                    "rule1":2.4,
                    "rule2":1.2,
                    "rule3":30.1
                }
            }
            ```

---

*   **llm-llm（大規模言語モデルユニット）**
    *   **目的:** 大規模モデルユニットであり、AI大規模モデル推論サービスを提供します。入力テキスト（将来的には他のモダリティも対応可能性あり）を処理して応答を生成したり、推論を実行したりします。
    *   **入力:** ZMQソケットからのテキスト入力（例：`llm.utf-8`というZMQトピック、または`asr.utf-8.stream`からの出力）。
    *   **出力:** ZMQソケットへのLLM生成テキスト（例：`llm.utf-8.stream`）。
    *   **設定:**
        *   `model`: 使用するLLMモデル（例："qwen2.5-0.5B-prefill-20e"）。
        *   `response_format`: 出力テキスト形式（例："llm.utf-8.stream"）。
        *   `input`: 入力テキストのソース（ZMQトピック名、例："llm.utf-8"。これは直接テキスト入力を受信できること、またはASRの出力からリンクできることを意味します）。
        *   `enoutput`: ブール値、出力ストリームを有効にするかどうか。
        *   `max_token_len`: 応答の最大トークン長（例：256）。
        *   `prompt`: LLMの動作をガイドするシステムプロンプト（例："あなたは様々な質問に答え、情報を提供できる知識豊富なアシスタントです。"）。
        *   セットアップ例：
            ```json
            {
                "request_id": "3",
                "work_id": "llm",
                "action": "setup",
                "object": "llm.setup",
                "data": {
                    "model": "qwen2.5-0.5B-prefill-20e",
                    "response_format": "llm.utf-8.stream",
                    "input": "llm.utf-8",
                    "enoutput": true,
                    "max_token_len": 256,
                    "prompt": "あなたは様々な質問に答え、情報を提供できる知識豊富なアシスタントです。"
                }
            }
            ```

---

*   **llm-melotts（Melodyテキスト音声合成ユニット）**
    *   **目的:** NPUアクセラレーション対応TTSユニットであり、テキスト音声合成および再生サービスを提供します。NPUで最適化されたテキストを可聴音声に変換します。
    *   **入力:** ZMQソケットからのテキスト入力（例：`tts.utf-8`というZMQトピック、通常は`llm-llm`から）。
    *   **出力:** 合成音声（例：`sys.pcm`）をZMQソケットに出力し、通常`llm-audio`で再生します。例の`enoutput: false`は、`llm-audio`がそれを処理する場合、再生用の別のリンクを必要とせずに、その出力が`sys.pcm`に結び付けられたオーディオ再生メカニズムによって直接消費される可能性があることを示唆しています。
    *   **設定:**
        *   `model`: 使用するTTSモデル（例："melotts_zh-cn"）。
        *   `response_format`: 出力オーディオ形式（例："sys.pcm"）。
        *   `input`: 入力テキストのソース（ZMQトピック名、例："tts.utf-8"）。
        *   `enoutput`: ブール値、出力ストリームを有効にするかどうか（例では`false`に設定されており、これは直接再生するか、事前定義されたオーディオ出力チャネルに送信することを意味する場合があります）。
        *   セットアップ例：
            ```json
            {
                "request_id": "4",
                "work_id": "melotts",
                "action": "setup",
                "object": "melotts.setup",
                "data": {
                    "model": "melotts_zh-cn",
                    "response_format": "sys.pcm",
                    "input": "tts.utf-8",
                    "enoutput": false
                }
            }
            ```

---

*   **llm-tts（CPUテキスト音声合成ユニット）**
    *   **目的:** CPU演算TTSユニットであり、テキスト音声合成および再生サービスを提供します。`llm-melotts`の代替であり、NPUアクセラレーションが利用できないか望ましくない場合に使用される可能性があります。
    *   **入力:** ZMQソケットからのテキスト入力（`llm-melotts`と同様、例：`tts.utf-8`というZMQトピック）。
    *   **出力:** ZMQソケットへの合成音声（`llm-melotts`と同様、例：`sys.pcm`）。
    *   **設定:** `llm-melotts`と同様ですが、CPUベースのモデルを使用します。特定のモデル名とパラメータは異なります。（提供されたREADMEには詳細なJSONの例はありませんが、機能は記載されています）。

---

*   **llm-camera（カメラインプットユニット）**
    *   **目的:** カメラデバイスからビデオフレームをキャプチャします。
    *   **入力:** カメラのデバイスパス（例："/dev/video0"）。設定メッセージ。
    *   **出力:** ZMQソケットへのRAWカメラフレーム（例：`camera.raw`）。
    *   **設定:**
        *   `response_format`: 出力フレーム形式（例："camera.raw"）。
        *   `input`: カメラデバイスパス（例："/dev/video0"）。
        *   `enoutput`: ブール値、出力ストリームを有効にするかどうか（例では`false`に設定されており、リンクされたユニットによる直接使用または内部処理を意味する場合があります）。
        *   `frame_width`: キャプチャされるフレームの幅（例：320）。
        *   `frame_height`: キャプチャされるフレームの高さ（例：320）。
        *   セットアップ例：
            ```json
            {
               "request_id":"4",
               "work_id":"camera",
               "action":"setup",
               "object":"camera.setup",
               "data":{
                  "response_format":"camera.raw",
                  "input":"/dev/video0",
                  "enoutput":false,
                  "frame_width":320,
                  "frame_height":320
               }
            }
            ```

---

*   **llm-yolo（物体検出ユニット）**
    *   **目的:** YOLOモデルを使用して入力画像上の物体検出を実行します。
    *   **入力:** ZMQソケットからの画像データ（例：`llm-camera.1000`インスタンスからの`camera.raw`というZMQトピック）。
    *   **出力:** ZMQソケットへの物体検出結果（例：バウンディングボックス、クラスラベル、`yolo.yolobox`形式）。
    *   **設定:**
        *   `model`: 使用するYOLOモデル（例："yolo11n"）。
        *   `response_format`: 検出結果の出力形式（例："yolo.yolobox"）。
        *   `input`: 画像データのソース（ZMQトピック名、例："camera.1000"、`llm-camera`のインスタンスを参照）。
        *   `enoutput`: ブール値、出力ストリームを有効にするかどうか。
        *   セットアップ例：
            ```json
            {
               "request_id":"5",
               "work_id":"yolo",
               "action":"setup",
               "object":"yolo.setup",
               "data":{
                  "model":"yolo11n",
                  "response_format":"yolo.yolobox",
                  "input":"camera.1000",
                  "enoutput":true
               }
            }
            ```

**一般ユニット構造:**

各ユニットについて、以下の情報が提供されます。

*   **[ユニット名]**
    *   **目的:** ユニットが行うことの簡単な説明。
    *   **入力:** 期待される入力データ形式とソース（ZMQトピックなど）。
    *   **出力:** 生成される出力データ形式と宛先（ZMQトピックなど）。
    *   **設定:** ユニットの特定のパラメータと設定。

## 3. システムワークフロー

このセクションでは、`llm_framework`を使用して、さまざまなユニットを特定の設定で接続することによって実装できる一般的な動作モードまたはワークフローについて説明します。

### 3.1. 音声アシスタントモード

**説明:** このワークフローは、音声制御アシスタント体験を可能にします。システムはキーワードをリッスンし、後続の音声を転写し、LLMで処理して応答を取得し、その応答を音声に再合成します。このモードは通常、オーケストレーションのための`llm-sys`ユニットと、RAWオーディオ入出力を処理するための`llm-audio`ユニットを含みます。

**ユニットシーケンスとデータフロー:**

1.  **`llm-audio`（暗黙的）:** PCMオーディオストリーム（`sys.pcm`というZMQトピック）を継続的に提供します。
2.  **`llm-kws`（キーワードスポッティング）:**
    *   **入力:** `llm-audio`からのPCMオーディオストリーム（`sys.pcm`トピック）。
    *   **アクション:** 事前定義されたキーワード（例："你好你好"）を検出します。
    *   **出力:** キーワード検出時のトリガーシグナル（例：`kws.bool`トピック）。
3.  **`llm-asr`（自動音声認識）:**
    *   **入力:** `llm-kws`トリガーによって起動された、`llm-audio`からのPCMオーディオストリーム（`sys.pcm`トピック）。
    *   **アクション:** 話し言葉のオーディオをテキストに転写します。
    *   **出力:** テキストストリーム（例：`asr.utf-8.stream`トピック）。
4.  **`llm-llm`（大規模言語モデル）:**
    *   **入力:** `llm-asr`からのテキストストリーム（`asr.utf-8.stream`トピック）。
    *   **アクション:** 入力テキストを処理し、推論を実行し、設定されたプロンプトとモデルに基づいて応答を生成します。
    *   **出力:** LLMの応答を含むテキストストリーム（例：`llm.utf-8.stream`トピック）。
5.  **`llm-melotts`または`llm-tts`（テキスト音声合成）:**
    *   **入力:** `llm-llm`からのテキストストリーム（`llm.utf-8.stream`トピック）。
    *   **アクション:** テキスト応答を音声に合成します。`llm-melotts`はNPUアクセラレーションを使用し、`llm-tts`はCPUを使用します。
    *   **出力:** 合成されたオーディオデータ（例：`sys.pcm`形式）。これは通常`llm-audio`を介して再生されます。

**簡略化されたデータフローパイプライン:**
PCMオーディオ（`llm-audio`）-> キーワード検出シグナル（`llm-kws`）-> テキスト（`llm-asr`）-> テキスト応答（`llm-llm`）-> 合成PCMオーディオ（`llm-melotts`/`llm-tts`、`llm-audio`経由で再生）。

**オーケストレーション:**
`llm-sys`ユニットは、これらの各ユニットのセットアップ（モデルのロード、`sys.pcm`や`asr.utf-8.stream`などの入出力ZMQトピックの定義など）と、記述されたパイプラインを形成するための入力と出力のリンキングを担当します。例えば、`llm-asr`はウェイクアップ後の転写を開始するために`llm-kws`にリンクされ、`llm-llm`は転写されたテキストを処理するために`llm-asr`にリンクされ、`llm-melotts`/`llm-tts`は応答を合成するために`llm-llm`にリンクされます。

### 3.2. CV（コンピュータビジョン）モード - 物体検出の例

**説明:** このワークフローは、視覚情報の処理に焦点を当てています。一般的な例は、カメラから画像をキャプチャし、その後、画像内の物体を識別して特定するために物体検出を実行することです。このモードはオーケストレーションに`llm-sys`ユニットを使用します。

**ユニットシーケンスとデータフロー:**

1.  **`llm-camera`（カメラインプット）:**
    *   **アクション:** 設定されたカメラデバイス（例：`/dev/video0`）から画像/ビデオフレームをキャプチャします。
    *   **出力:** RAW画像データストリーム（例：`camera.raw`というZMQトピック）。
2.  **`llm-yolo`（物体検出）:**
    *   **入力:** `llm-camera`のインスタンス（例：`camera.1000`）からのRAW画像データストリーム（`camera.raw`トピック）。
    *   **アクション:** YOLOモデル（例："yolo11n"）を使用して画像を処理し、物体を検出します。
    *   **出力:** 物体検出結果。通常、バウンディングボックス、物体クラス、信頼スコアを含みます（例：`yolo.yolobox`形式のZMQトピック）。

**簡略化されたデータフローパイプライン:**
RAW画像データ（`llm-camera`）-> 物体検出結果（`llm-yolo`）。

**オーケストレーション:**
`llm-sys`ユニットは、`llm-camera`ユニット（解像度などのカメラパラメータを指定）と`llm-yolo`ユニット（モデルと入力ソースを指定）をセットアップします。次に、`llm-camera`インスタンスの出力を`llm-yolo`インスタンスの入力にリンクして、処理パイプラインを作成します。`llm-yolo`からの結果は、他のアプリケーションやユニットが消費するためにZMQトピック経由で公開できます。

## 4. 通信プロトコル

`llm_framework`内のユニットは、高性能な非同期メッセージングライブラリである**ZeroMQ（ZMQ）**を使用して通信します。これにより、ユニットが独立して、または協調して動作できる分散アーキテクチャが可能になります。データと制御シグナルは、標準化された**JSONメッセージ形式**を使用してZMQチャネル（トピック）を介して交換されます。

**一般的なJSONメッセージ構造（リクエスト）:**

ユニットに送信される制御メッセージ（通常は`llm-sys`経由または設定のために直接）は、共通の構造に従います。

```json
{
    "request_id": "string", // リクエストの一意識別子
    "work_id": "string",    // ターゲットユニットまたはシステムコンポーネント（例："sys"、"kws"、"asr.1001"）
    "action": "string",     // 実行する操作（例："reset"、"setup"、"link"）
    "object": "string",     // アクションの対象や種類を指定（例："kws.setup"、"work_id"）
    "data": {}              // 操作に固有のパラメータを含むJSONオブジェクト
}
```

**一般的なアクションメッセージ:**

*   **`reset`（システムレベル）:**
    システムまたは特定のユニットの状態をリセットするために使用されます。
    *例（システムリセット）:*
    ```json
    {
        "request_id": "11212155",
        "work_id": "sys",
        "action": "reset"
    }
    ```

*   **`setup`（ユニット設定）:**
    モデル、入出力ZMQトピック、その他の設定を含む運用パラメータで特定のユニットを初期化および設定するために使用されます。
    *例（`llm-kws`ユニットのセットアップ）:*
    ```json
    {
        "request_id": "1",
        "work_id": "kws",
        "action": "setup",
        "object": "kws.setup",
        "data": {
            "model": "sherpa-onnx-kws-zipformer-wenetspeech-3.3M-2024-01-01",
            "response_format": "kws.bool",
            "input": "sys.pcm", // 入力オーディオ用のZMQトピック
            "enoutput": true,   // 出力パブリッシュを有効にする
            "kws": "你好你好"     // 検出するキーワード
        }
    }
    ```
    セットアップが成功すると、ユニットインスタンスが作成されます（例：`kws.1000`）。

*   **`link`（ユニットの入出力接続）:**
    あるユニットインスタンスの出力チャネル（ZMQトピック）を別のユニットインスタンスの入力チャネル（ZMQトピック）に接続することにより、データフローパイプラインを確立するために使用されます。
    *例（`asr.1001`を`kws.1000`の出力を購読するようにリンクする）:*
    ```json
    {
        "request_id": "2",
        "work_id": "asr.1001", // ターゲットユニットインスタンス
        "action": "link",
        "object": "work_id",   // work_idによるリンキングを指定
        "data": "kws.1000"     // 出力が消費されるソースユニットインスタンス
    }
    ```

**データ交換:**

ユニットは処理を実行し、その結果を設定された出力ZMQチャネル（トピック）に**公開（publish）**します。この出力を使用するように設定された他のユニット（`link`メッセージまたは入力トピックの直接設定による）は、これらのチャネルを**購読（subscribe）**してデータを受信できます。これにより、StackFlowアーキテクチャ内の内部データフローが可能になり、さまざまなユニットが連携して動作できるようになります。データ自体は通常、JSON構造内にカプセル化され、多くの場合、`created`（タイムスタンプ）、`data`（ペイロード）、`error`（もしあれば）、`object`、`request_id`、および`work_id`（公開ユニットインスタンスの）などのフィールドが含まれます。

ユニットからの応答/ステータスメッセージの例（公開されたデータを表すこともできます）：
```json
{
    "created": 1731488371,
    "data": "None", // データメッセージの場合は実際のペイロード
    "error": {"code": 0, "message": ""},
    "object": "None",
    "request_id": "3", // 初期リクエストに対応
    "work_id": "asr.1001" // 応答/データを提供するユニットインスタンス
}
```

## 5. 設定

StackFlowユニットの設定は**JSONファイル**を介して管理されます。これらのファイルは、ユニットの運用パラメータと、それらが使用するAIモデルのパラメータの両方を定義します。

**設定ファイルの場所:**

設定ファイルが通常配置される主要なディレクトリは次のとおりです。

*   `/opt/m5stack/data/models/`（主にモデルファイルと関連するモデル設定用）
*   `/opt/m5stack/share/`（多くの場合、ユニット運用パラメータ設定やその他の共有リソース用）

**設定の種類:**

1.  **ユニット運用パラメータ設定:**
    *   これらの設定は、ユニットの動作方法、ZMQ入出力トピック、特定のハードウェア設定（もしあれば）、およびその他の機能的側面を定義します。
    *   例としては、「通信プロトコル」セクションの`setup`メッセージに見られるように、`input`ソース（ZMQトピック名、例："sys.pcm"）、`response_format`（例："asr.utf-8.stream"）、および`enoutput`フラグの設定が含まれます。

2.  **モデル運用パラメータ設定:**
    *   これらの設定は、ユニットが使用するAIモデルに固有です。これには、モデルファイルへのパス、前処理/後処理パラメータ、推論設定（LLMの`max_token_len`やASRの`rule1, rule2, rule3`など）、およびプロンプトが含まれる場合があります。
    *   フレームワークは柔軟性を提供します。「すべてのユニットは運用パラメータで完全に設定でき、同じデータフロー処理シナリオ内でモデルの交換とモデルパラメータの変更が可能」です。これは、これらの設定ファイルを変更することで、ユーザーがコアユニットコードを変更せずにユニットの動作と使用するモデルを適応できることを意味します。

例えば、`llm-llm`ユニットの`setup`データには、`model: "qwen2.5-0.5B-prefill-20e"`と`prompt: "あなたは知識豊富なアシスタントです..."`が含まれています。これらは通常、そのような設定ファイルからロードされるか、その中で定義されます。同様に、`llm-kws`ユニットの`model: "sherpa-onnx-kws-zipformer-wenetspeech-3.3M-2024-01-01"`と`kws: "你好你好"`もその設定の一部です。

## 6. 用語集（オプションですが推奨）

*   **StackFlow:** データが一連の処理段階（ユニット）を順次流れるアーキテクチャパターン。
*   **ユニット:** `llm_framework`内のモジュールコンポーネントで、特定の処理タスクを担当します。
*   **ZMQ（ZeroMQ）:** ユニット間通信に使用される高性能な非同期メッセージングライブラリ。
*   **エンドポイント:** メッセージの送受信に使用されるZMQアドレス（例：`tcp://localhost:5555`）。
*   **メッセージ:** 通常JSON形式のデータパケットで、ユニット間で交換されます。
*   **ワークフロー:** より大きなタスクを達成するために設計された、接続されたユニットの特定の設定とシーケンス。
*   **ZMQトピック (ZMQ Topic):** ZMQのPUB/SUBパターンで使用されるメッセージフィルタリングの仕組み。ユニットは特定のトピックにメッセージを公開し、他のユニットはそのトピックを購読することで関連するメッセージのみを受信します。仕様書中の`input`や`output`で参照される`sys.pcm`などは、これらのZMQトピック名として機能します。
