# llm-tts (Text-to-Speech)

The `llm-tts` unit provides text-to-speech (TTS) services, converting input text into audible speech. It supports various models, including options for Chinese and English languages. This unit is distinct from `llm-melotts` and may use different underlying TTS engines (e.g., non-NPU accelerated engines).

## General API Call Conventions

API calls to `llm-tts` are made via JSON messages.

### Request Structure

A standard request to an `llm-tts` API follows this structure:

```json
{
  "request_id": "client_generated_uuid_or_counter",
  "work_id": "tts_or_tts.instance_id",
  "action": "api_action_name",
  "object": "optional_object_type_string", // If applicable
  "data": { /* API-specific payload */ }     // Or string for some APIs
}
```

-   `request_id` (string, mandatory): A unique client-generated identifier for correlating requests with responses.
-   `work_id` (string, mandatory):
    -   For initial setup or general queries: `"tts"`.
    -   For operations on a specific TTS task instance: `"tts.XXXX"` (e.g., `"tts.1003"`), where `XXXX` is the instance ID returned by a successful `setup` call.
-   `action` (string, mandatory): The API action to invoke (e.g., `"setup"`, `"inference"`).
-   `object` (string, optional): Specifies the type or context of the data being sent (e.g., `"tts.setup"`, `"tts.utf-8"`).
-   `data` (object or string, optional): The payload for the API call.

### Response Structure

**Success Response (for most API calls):**

Indicates the API call was accepted and processed successfully.

```json
{
  "request_id": "mirrored_from_request",
  "work_id": "tts_or_tts.instance_id", // Mirrored or updated
  "action": "api_action_name",        // Mirrored from the request
  "created": 1678886400,              // Integer: Unix timestamp of response generation
  "code": 0,                          // Integer: 0 indicates success
  "message": "OK",                    // String: Success message
  "data": { /* API-specific data */ } // Optional: Payload returned by the API
}
```
-   For the `inference` API, this synchronous response only acknowledges the request; the actual synthesized audio is sent asynchronously or played back.
-   If an API call results in the creation of a new task instance (e.g., `setup`), the `work_id` in the response and in `data.work_id` will be the new instance ID.

**Error Response:**

Indicates a failure during API call processing.

```json
{
  "request_id": "mirrored_from_request",
  "work_id": "tts_or_tts.instance_id",
  "action": "api_action_name",        // Mirrored from the request
  "created": 1678886400,              // Integer: Unix timestamp of response generation
  "error": {
    "code": -1,                       // Integer: Non-zero error code
    "message": "Error description"    // String: Detailed error message
  }
}
```

**Common Error Codes:**

-   `-2`: Invalid JSON format in the request `data`.
-   `-3`: TTS engine initialization failed.
-   `-5`: Model loading failed (e.g., model files or required data not found).
-   `-6`: Specified TTS task instance (e.g., `"tts.1003"`) does not exist.
-   `-11`: Generic error during speech synthesis or internal processing.
-   `-20`: Error related to input source linking or data subscription.
-   `-21`: Task limit reached.
-   `-23`: Error processing input text (e.g., text too long, character encoding issues).

## Data Input and Output (Text and Synthesized Speech)

### Input Data (Text for Synthesis)

The `llm-tts` unit can receive text for synthesis in several ways:

1.  **Via `inference` API to a specific `tts.XXXX` instance:**
    *   **Non-streaming text (`object: "tts.utf-8"`)**:
        -   The `data` field is a single string containing the full text to be synthesized.
    *   **Streaming text (`object: "tts.utf-8.stream"`)**:
        -   The `data` field is a JSON object: `{"index": <integer>, "delta": "<text_chunk>", "finish": <boolean>}`.
        -   Text is accumulated internally. Synthesis of audio segments typically occurs when punctuation marks (like comma, period, exclamation mark, question mark) are encountered in the accumulated text, or when `finish` is `true`.

2.  **Via Linked Units (configured in `setup` API's `input` parameter):**
    *   **`"tts.utf-8"` or `"tts.utf-8.stream"`**: The instance listens for text sent to its own `work_id` using the `inference` API as described above.
    *   **`"llm.XXXX"` or `"vlm.XXXX"`**: The TTS instance subscribes to the output of a specified LLM or VLM unit. The text generated by these units is processed as input for synthesis.
    *   **`"asr.XXXX"`**: The TTS instance subscribes to the output of an ASR unit. The transcribed text is used as input for synthesis.
    *   **`"kws.XXXX"`**: The TTS instance subscribes to events from a KWS unit. When a keyword is detected, this typically triggers an interrupt of any ongoing TTS from a `superior_id_` (like an LLM) and re-establishes the subscription to that `superior_id_`. This is more of a control flow mechanism than direct synthesis of KWS event data.

### Output Data (Synthesized Speech)

Synthesized audio can be handled in two main ways:

1.  **Direct Playback via `llm_audio` (`response_format` contains `"sys.pcm"` or `"sys"`, and `enaudio: true`)**
    -   If `response_format` is set to `"sys.pcm"` (or similar) and `enaudio` is `true` (default is `true`), the generated PCM audio data is sent segment by segment to the `llm_audio` unit for immediate playback (using `audio->queue_play`).
    -   This is the primary mode for direct auditory feedback.

2.  **API Push of Audio Data (`enoutput: true`)**
    -   If `enoutput` is `true`, the synthesized audio data (PCM) is Base64 encoded and pushed asynchronously to the client that initiated the task.
    -   **Streaming Output (`response_format: "tts.pcm.base64.stream"`)**:
        -   Audio is sent in chunks as they are synthesized.
        -   JSON Structure per Chunk:
            ```json
            {
              "request_id": "<original_inference_request_id>",
              "work_id": "tts.XXXX",
              "action": "tts_audio_event", // Example conventional action name
              "object": "tts.pcm.base64.stream",
              "created": 1678886410,
              "code": 0,
              "message": "OK",
              "data": {
                "index": 0, // Sequence number of this audio chunk
                "delta": "<Base64_encoded_PCM_audio_chunk>",
                "finish": false // True for the very last chunk of the entire synthesis task
              }
            }
            ```
    -   **Non-Streaming Output (`response_format: "tts.pcm.base64"`)**:
        -   The entire synthesized audio is sent as a single Base64 encoded string after the full input text has been processed.
        -   JSON Structure:
            ```json
            {
              "request_id": "<original_inference_request_id>",
              "work_id": "tts.XXXX",
              "action": "tts_audio_event", // Example conventional action name
              "object": "tts.pcm.base64",
              "created": 1678886415,
              "code": 0,
              "message": "OK",
              "data": "<Full_Base64_encoded_PCM_audio>"
            }
            ```
    -   The `request_id` in these asynchronous messages corresponds to the `inference` API call that provided the text.

## API Reference

### **setup**

Initializes and configures a new Text-to-Speech (TTS) task instance.

-   **`work_id` in request**: `"tts"`
-   **`work_id` in response (success)**: `"tts.XXXX"` (e.g., `"tts.1003"`)

**Request Parameters:**

| Parameter              | Type          | Required | Default (from Model JSON if applicable) | Description                                                                                                                                                                                                                            |
|------------------------|---------------|----------|-----------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `object`               | string        | Yes      | N/A                                     | Must be `"tts.setup"`.                                                                                                                                                                                                                 |
| `data.model`           | string        | Yes      | N/A                                     | Name of the TTS model configuration file (without `.json`). Examples: `"single-speaker-english-fast"`, `"single-speaker-fast-mini"`. Models are located in `projects/llm_framework/main_tts/models/`.                               |
| `data.response_format` | string        | Yes      | N/A                                     | Defines how audio output is handled. `"sys.pcm"` (or any format containing "sys") enables direct playback via `llm_audio` if `enaudio` is true. Formats like `"tts.pcm.base64"` or `"tts.pcm.base64.stream"` enable API push of audio data if `enoutput` is also true. |
| `data.input`           | string/array  | Yes      | N/A                                     | Input source(s) for text. Examples: `"tts.utf-8"` (for direct API input to this instance), `"llm.1002"` (to link to an LLM's output). See "Input Data" section.                                                                    |
| `data.enoutput`        | boolean       | No       | `false` (as per initial doc example)    | If `true`, enables asynchronous pushing of Base64 encoded PCM audio data to the client, according to `response_format`.                                                                                                       |
| `data.enaudio`         | boolean       | No       | `true`                                  | If `true` and `response_format` indicates system audio (e.g., "sys.pcm"), plays synthesized audio via `llm_audio`. If `false`, audio is not played even if `response_format` is "sys.pcm".                                           |
| `data.mode_param`      | object        | No       | {}                                      | Allows overriding specific parameters from the model's JSON, e.g., `{"spacker_speed": 1.0, "spacker_role": 0}`. Supported overrides depend on `main.cpp` implementation. |

**Request Example:**
```json
{
  "request_id": "setup_tts_001",
  "work_id": "tts",
  "action": "setup",
  "object": "tts.setup",
  "data": {
    "model": "single-speaker-english-fast",
    "response_format": "sys.pcm", // Play audio directly
    "input": "tts.utf-8",
    "enoutput": false, 
    "enaudio": true,
    "mode_param": {
      "spacker_speed": 1.0 
    }
  }
}
```

**Response (Success):**
```json
{
  "request_id": "setup_tts_001",
  "work_id": "tts.1003", // New TTS task instance ID
  "action": "setup",
  "created": 1678886400,
  "code": 0,
  "message": "OK",
  "data": {
    "work_id": "tts.1003" // Confirms the created instance ID
  }
}
```

### **inference**

Submits text to a specific TTS task instance for speech synthesis. The audio output is handled asynchronously.

-   **`work_id` in request**: `"tts.XXXX"` (specific TTS task instance ID)

**Request Parameters:**

| Parameter | Type          | Required | Default | Description                                                                                                                               |
|-----------|---------------|----------|---------|-------------------------------------------------------------------------------------------------------------------------------------------|
| `object`  | string        | Yes      | N/A     | Specifies the format of the input text: `"tts.utf-8"` (for a single, complete text) or `"tts.utf-8.stream"` (for a chunked text).         |
| `data`    | string/object | Yes      | N/A     | If `object` is `"tts.utf-8"`, `data` is a string. If `object` is `"tts.utf-8.stream"`, `data` is an object: `{"index": <int>, "delta": "<text_chunk>", "finish": <boolean>}`. |

**Request Example (Non-streaming):**
```json
{
  "request_id": "infer_tts_002",
  "work_id": "tts.1003",
  "action": "inference",
  "object": "tts.utf-8",
  "data": "Hello world, this is a test."
}
```

**Response (Success - Request Accepted):**
This response only confirms that the text has been received for synthesis.
```json
{
  "request_id": "infer_tts_002",
  "work_id": "tts.1003",
  "action": "inference",
  "created": 1678886402,
  "code": 0,
  "message": "OK"
}
```

## Relation to Model Configuration Files

The `llm-tts` unit relies on model-specific JSON configuration files (e.g., `mode_single-speaker-english-fast.json`) located in the `projects/llm_framework/main_tts/models/` directory or a system-wide model path.

Key aspects of these model configuration files:
-   **`mode`**: Model name used in the `setup` API (e.g., `"single-speaker-english-fast"`).
-   **`type`**: Unit type, typically `"tts"`.
-   **`capabilities`**: Describes function, e.g., `"tts"`, `"English"`.
-   **`mode_param` Object**: Contains core parameters for the TTS engine:
    -   `ttsModelName` (string): The filename of the actual TTS model (e.g., `"single_speaker_english_fast.bin"`). This file is located within the model's specific directory.
    -   `spacker_speed` (float, optional): Default speaking speed (e.g., `1.0`). Can be overridden by `setup`'s `mode_param`.
    -   `spacker_role` (integer, optional): Default speaker ID/role, if the model supports multiple speakers. Can be overridden by `setup`'s `mode_param`.
    -   `sample_rate` (integer, optional): The sample rate the model was trained on or expects for output.
    -   `awake_delay` (integer): Delay in milliseconds used when linked with KWS.

These parameters are loaded when a task is set up with a specific model.

## Important Notes
-   **Concurrency**: The note "The same type of unit cannot have multiple units working simultaneously" applies to TTS units. Running multiple TTS instances (e.g., two `llm-tts` or an `llm-tts` and an `llm-melotts`) concurrently might lead to resource conflicts or issues with audio playback.
-   **Audio Playback**: When `enaudio: true` and `response_format` indicates system audio (e.g., "sys.pcm"), the `llm-tts` unit relies on the `llm_audio` unit for playback. Ensure `llm_audio` is functional.
-   **Text Segmentation**: The unit processes input text in segments, typically delimited by punctuation (commas, periods, question marks, exclamation marks), allowing for more responsive synthesis of longer texts.
